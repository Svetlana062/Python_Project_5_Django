# Курсовой проект 5. Трекер привычек

## Описание
В 2018 году Джеймс Клир написал книгу «Атомные привычки», которая
посвящена приобретению новых полезных привычек и искоренению старых
плохих привычек. Заказчик прочитал книгу, впечатлился и попросил
реализовать трекер полезных привычек.

В рамках учебного курсового проекта реализована бэкенд-часть SPA
веб-приложения.

Этот проект представляет собой систему для отслеживания привычек с 
использованием Django REST Framework и Celery для асинхронных задач.
Пользователи могут создавать, просматривать и управлять своими
привычками, а также делиться публичными привычками с другими.

## Основные возможности
* Аутентификация и управление профилем пользователя;
* Создание, просмотр, редактирование и удаление привычек;
* Публичные и личные привычки;
* Отправка уведомлений или сообщений через Celery (например, в Telegram);
* Разграничение прав доступа (администратор, пользователь);
* Возможность делиться публичными привычками.


### Требования к окружению
* Python 3.13+

### Установка
* Клонируйте репозиторий:
```
git clone https://github.com/Svetlana062/Python_Project_5_Django.git
```
* Установите зависимости:
```
pip install -r requirements.txt
```
* Войдите в виртуальное окружение:
```
poetry shell
```
* Выполните миграции базы данных:
```
python manage.py migrate
```
* Запустите сервер разработки:
```
python manage.py runserver
```
API будет доступен по адресу: http://127.0.0.1:8000/


### Запуск на удаленном сервере
1. Настройте сервер:
* Убедитесь, что на сервере установлен Docker и Docker Compose;
* Создайте файл .env в корневом каталоге проекта, если он еще не создан, и добавьте
необходимые переменные окружения.

2. Соберите и запустите контейнеры:
```
docker-compose up --build -d
```

Теперь приложение доступно по адресу: http://89.169.179.247


### Инструкция по настройке сервера и CI/CD

1. Настройка сервера:
* Убедитесь, что на сервере установлен Docker и Docker Compose;
* Настройте переменные окружения в файле .env.

2. CI/CD:
* Проект использует GitHub Actions для автоматизации CI/CD. Файл конфигурации
находится по пути: .github/workflows/ci.yml;
* При каждом push или pull request запускаются тесты на сервере с
использованием PostgreSQL, а также происходит сборка и развертывание приложения.

  
## Структура проекта
Данный проект содержит два Django-приложения:

1. users (реализует управление пользователями):
* Модель пользователя (CustomUser) с полями для авторизации, статусом активности и ролью
администратора (myproject/users/models.py);
* Миграции базы данных (myproject/users/migrations/);
* Команда для создания суперпользователя с предустановленными данными
(myproject/users/management/commands/csu.py);
* Сериализатор модели пользователя для API (myproject/users/serializers.py);
* Формы для регистрации, входа и создания новых пользователей (myproject/users/forms.py);
* ViewSet для работы с пользователями через API (myproject/users/views.py). 
* Разграничение прав доступа - permissions (myproject\users\permissions.py)

2. habit_tracker (реализует управление курсами и уроками):
* Модель привычки Habit (myproject/habit_tracker/models.py);
* Миграции базы данных (myproject/habit_tracker/migrations/);
* Сериализатор для API (myproject/habit_tracker/serializers.py);
* ViewSet для работы с привычками (myproject/habit_tracker/views.py);
* Задачи Celery для отправки сообщений в Telegram (myproject/habit_tracker/task.py);
* Маршруты API (myproject/habit_tracker/urls.py).
